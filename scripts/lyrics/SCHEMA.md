# Lyrics data schema

The player reads a single file, `src/assets/catalogs/lyrics.json`, the same way it
already reads `album-notes.json` (fetched once, keyed by album). Lyrics are keyed
**album title → track number**, matching `yura.json` so the player can look them up
from the currently-playing track with no extra ids.

```jsonc
{
  "<album title exactly as in yura.json>": {
    "<track number as string>": {
      "title": "…",                 // track title, for cross-checking against the catalog
      "jp":     <Block> | null,     // Japanese source lyrics
      "romaji": <Block> | null,     // transliteration
      "en":     <Block> | null,     // English translation
      "flags":  ["…"]               // optional: uncertainty / TODO notes (not shown to users)
    }
  }
}
```

### `<Block>`

Every language is an attributed block. The attribution is what the app shows at the
**end of the lyrics** so a reader always knows who produced that text and whether it
is machine- or human-made.

```jsonc
{
  "lines": ["line 1", "line 2", "", "line 4"],   // one array entry per displayed line; "" = blank line / stanza break
  "by":    "Claude (Opus 4.8)",                    // display credit — a person's handle, a site, or the AI model
  "kind":  "ai",                                   // one of: official | transcription | ai | human
  "src":   "歌詞/03.txt (community booklet transcription)", // provenance, free text or URL
  "date":  "2026-08-07"                            // ISO date the block was produced/added
}
```

`kind` values:

| kind            | meaning                                                                 | example `by`            |
|-----------------|-------------------------------------------------------------------------|-------------------------|
| `official`      | Straight from the official booklet / label (typed or clean scan)        | `葉月ゆら (booklet)`     |
| `transcription` | A person typed the JP out from a booklet scan                           | `南瓜虎@tieba`          |
| `ai`            | Generated by an AI model (romaji or EN pass)                            | `Claude (Opus 4.8)`     |
| `human`         | A person's transliteration or translation                              | `meriole`               |

### Rules

- **Line arrays stay aligned.** `jp`, `romaji`, and `en` should have the **same number
  of lines** wherever possible so the app can show them side-by-side and, later, time-code
  them. A blank line is `""` in every language, not a dropped entry. When a translation
  genuinely must merge/split lines, keep the count matched by leaving `""` padding and note
  it in `flags`.
- **AI blocks are placeholders.** Anything with `kind: "ai"` is meant to be replaced by a
  human later. The app can style it differently ("machine translation") off `kind`.
- **Never invent a `jp` block.** JP only ever comes from a real source (booklet text file,
  booklet scan transcription, or official). romaji/en may be `ai`.
- Absent language → `null` (the player shows its empty state for that language tab).
- Album/track keys must match `yura.json`. The ingest scripts map the archive's folder
  names (catalog codes + dates) onto the catalog titles; see `README.md`.
